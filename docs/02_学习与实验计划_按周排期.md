# 一　这份计划怎么用

这份文档不是"理想情况下的学习路线"，而是一张按日历排死的施工表。它的排法遵循四条规则，先说明规则，你才知道为什么某一周只有一件事。

- **每周只有一个主任务**。一周内允许穿插阅读和小修，但只允许有一个"这周必须交付"的东西。本科毕设最常见的失败不是能力不够，而是每周都很忙、每周都没有可检查的产出。
- **先有实验，后有方法**。第 9 周就要跑出第一份全量数据（每题的可信度分数 + 对错），之后所有的阈值、校准、消融都在这份 CSV 上做。这样即使核心方法不成立，你也已经有一篇"信号有效性分析"型论文的素材，不会满盘皆输。
- **里程碑倒排**。学院的开题（12-25）、中期（03-15 至 03-26）、内审查重（04-26 起）、答辩（05-18 起）是硬边界，不可协商。本计划把"结果冻结"放在中期之前，把"写作"分散到 4 次，而不是留到最后一个月。
- **算力按需错峰**。建索引、全量生成这类一次性重活放在寒假前和寒假初，宿舍/实验室卡空闲时段（夜间、周末）跑批；白天只做读、写、调脚本这类不吃卡的工作。

计划里反复出现的三个缩写：**MVS**（最小可行系统，一条主链路 + 一条离线评测旁路）、**α**（允许的错误率上限，例如 0.05）、**τ**（拒答阈值，在独立校准集上确定）。

# 三　P0 预研（W1–W3）：把题目钉死，把环境跑通

这三周的目标不是学知识，而是把三个不确定性消掉：题目能不能被导师接受、数据能不能下载、代码能不能跑起来。

## 3.1 W1（11/02–11/08）：确认题目 + 装环境 + 下载数据

本周七件事，按顺序做，一天一件：

1. **把收敛后的题目发给校内导师**，重点确认三件事：是否接受"只做拒答、不做重新生成"；是否接受"不训练任何模型、只做校准与决策"；是否需要在中期前给出一版可用演示。导师的这三句话决定后面 20 周的范围。
2. **确认做院内、跨院还是校外毕设**。若走校外，10-31 前必须把《校外完成本科毕业设计（论文）审批表》和协议交到教三楼 811；已过期的要第一时间联系王老师问补交口径。境外/校外一律回校答辩。
3. 装 Python 环境：`conda create -n ragqa python=3.10`，装 `torch`（按服务器 CUDA 版本）、`transformers`、`sentence-transformers`、`faiss-cpu`、`bm25s`（不要用 `rank_bm25`，它在百万级语料上要吃 10—20 GB 内存）、`jieba`、`pandas`、`scikit-learn`、`matplotlib`、`tqdm`。本周先只装 CPU 版，能跑通即可。
4. 下载 CRAG 公开数据（HuggingFace 上 `crag` 数据集与官方 GitHub 里的检索语料），确认题量、字段、5 个领域名称，把原始文件放到 `data/raw/`，**不要改动原始文件**。
5. 下载 RGB 数据集备用（本周只下载，不做实验）。
6. 建 Git 仓库，写 `README.md`：一段话说明题目、一段话说明目录、一段话说明复现命令。第一周就把这件事做掉，后面 30 周的实验记录都靠它。
7. 读第一批论文（见第五章 Batch A，5 篇），每篇在 `notes/` 下写 200 字摘要，格式固定：问题 / 方法 / 指标 / 我能借用什么。

本周验收：能用自己的话在 3 分钟内讲清"我要解决什么问题、用什么信号、在什么数据上评、和谁比"，且导师认可这个范围。

## 3.2 W2（11/09–11/15）：系统选题 + 第一个能跑的东西

- **11-09 00:00 至 11-16 00:00 必须在教务系统完成选题**（毕业设计 → 选题管理 → 学生选题），状态要变成"确定"才算完成。最多填 3 个平行志愿，被任一教师反选后不得无故更换，所以第一志愿要填你已经和导师谈妥的那个。
- 代码任务：用 BM25 在 20 道题上跑通"检索 top-5 → 拼 prompt → 调一次模型 → 输出答案"的闭环。模型这周可以用 API（便宜、免装），先把链路跑通。
- 数据集任务：把 CRAG 语料按固定窗口切块（建议 384 token、重叠 64），落到 `data/chunks/`，统计块数与平均长度——这个数字决定后面建索引要多久。
- 读第二批论文（Batch B 前 2 篇）。
- 本周验收：`python -m src.run --limit 20 --retriever bm25` 一条命令能出 20 行 JSONL，每行含问题、检索到的块、答案、金标。

## 3.3 W3（11/16–11/20）：任务书定稿

任务书由导师下达、你配合填写。本周把六栏内容写成定稿，直接可用《01_毕设完成路线与技术调研》第九章的文字：

- 主要内容：三条研究内容（评测框架 / 断言级充分性评分 / 风险受控拒答），不要写成六件事。
- 主要技术要求：固定检索与生成组件、独立校准集、风险—覆盖指标、可复现快照。
- 主要参考文献：从第十章挑 10 篇，按 GB/T 7714 格式排好。
- 进度安排：按本文件第二章的四段式写（11–12 月框架与开题；1–2 月评分、校准与主实验；3 月消融与中期；4–5 月论文、查重与答辩）。
- 题目类型勾"研究设计类"，题目来源按实际填。

本周验收：任务书提交且导师签字；同时确认服务器（机器三档与云平台报价见《03》第四章，环境命令见第五章），因为第 4 周就要建索引。

# 四　P1 开题（W4–W8）：五周把"能跑的实验"变成"能开题的方案"

开题报告 11-30 至 12-25 提交并接受学院检查。这五周的技术目标只有一个：**在 200 题上跑出第一张风险—覆盖曲线**。有了这张图，开题报告的"研究方法及措施"和"研究步骤与进度"两节就有实物撑着，不会被问倒。

## 4.1 W4（11/23–11/29）：全量建索引 + 评测脚本

- 向量化：用 `bge-m3` 把全部块编码，落到 `.npy`，再建 FAISS 的 `IndexFlatIP`（数据量在百万级以内，暴力检索足够快，不必上 HNSW）。同时建 BM25 索引（`rank_bm25` 或 `bm25s`）。
- 评测脚本 `src/eval.py`：输入结果 JSONL，输出 CRAG 三档判定（Correct / Incorrect / Missing）、覆盖率、选择性风险、AURC、ECE。指标公式见《01》第六章，先写死实现，后面所有实验都调它。
- 本周验收：给定任意结果文件，`python -m src.eval --pred results/xxx.jsonl` 能打印一张指标表；索引能在 1 秒内返回 top-20。

## 4.2 W5（11/30–12/06）：生成管线 + 200 题首跑

- 生成两条路都要有：本地 vLLM（`vllm serve` 起 OpenAI 兼容服务）和 API（同一套 `openai` SDK 客户端，只换 `base_url` 与模型名）。配置化切换是任务书里的承诺，也是第 16 周"换生成模型"消融的前提。
- Prompt 固定版本号（`prompt_v1`），要求模型输出 JSON：`{"answer": ..., "citations": [块编号]}`。加引用编号是后面断言级校验的入口，这一步不要省。
- 本周验收：200 题跑完，落盘 JSONL；人工看 10 条，确认答案格式正确、引用编号能在检索块里对上。

## 4.3 W6（12/07–12/13）：断言分解 + NLI 打分

- 断言分解：用 LLM 把答案拆成原子断言（一句一断言、不含指代、可独立判真假），落 `claims.jsonl`。抽 20 题人工检查，断言数过多（>8）或过少（<1）都要调 prompt。
- 支持度打分：先用现成 NLI/事实核查模型（MiniCheck、DeBERTa-MNLI 或 bge-reranker 做相关性近似），对"断言 × 证据"逐对打分，得到支持矩阵。
- 计算两个核心信号：断言覆盖率（被至少一条证据支持的断言比例）、矛盾度（被证据反驳的断言比例）。
- 本周验收：能画出"覆盖率 vs 答案正确"的散点/分箱图，并肉眼看出单调关系；若看不出，先别急着上融合，回去查断言粒度与证据数量。

## 4.4 W7（12/14–12/20）：基线与曲线

- 补齐前三组基线：永远回答、永远拒答、模型自评阈值（让模型输出 1–10 置信度）。
- 写 `src/risk_coverage.py`：输入分数与对错，扫 τ 画 risk-coverage 曲线、算 AURC。这张图是开题报告里最有说服力的一张。
- 开题报告开始写：本周完成"选题背景与意义"和"研究的基本内容与拟解决的主要问题"。

## 4.5 W8（12/21–12/25）：开题定稿

- 开题报告 ≥1500 字、参考文献 ≥10 篇（近五年为主）。结构按模板五段写：背景与意义 / 研究内容与拟解决问题 / 研究方法及措施 / 工作步骤与进度 / 主要参考文献。
- 直接把 W7 的风险—覆盖曲线、W4 的指标表放进报告，比任何文字都有力。
- 准备 5 分钟开题陈述：问题（1 句）→ 为什么现有方法不够（1 句）→ 我的信号（1 句）→ 怎么验（1 句）→ 进度（1 句）。
- 本周验收：开题报告上传系统、导师审核通过；PPT 能讲 5 分钟不超时。

# 五　P2 主实验（W9–W19）：十一周把主表做出来

这是全篇最重的一段，跨期末、寒假、春节。核心策略是：**期末周只做低强度工作（写、读、整理），寒假集中跑重活**。

## 5.1 W9–W11（12/28–01/17）：全量数据落地

- W9：全量生成。4.4k 题，用 vLLM 的离线批处理（`LLM.generate` 传一个 4400 条的 prompt 列表、并发开满）约 **0.6—0.9 小时**；"8—12 小时"是并发约等于 1 的串行跑法，不要那样跑。同一周还要留时间给重排（4.4k×5 候选约 22—44 万对，单次 0.5—0.6 小时——**这是本课题最大的单项 GPU 消耗，比生成还贵**）。API 版本约几十元。**一次跑完并落盘**，不要边跑边改 prompt。
- W10：全量断言校验。每题 3 条断言 × 5 条证据 ≈ 15 次前向，全量约 6.6 万次，单卡 2—3 小时。
- W11：把每题的信号拼成一张宽表 `features.csv`：`qid, domain, question, answer, correct(0/1/2), coverage, contradiction, top1_score, rerank_score, self_conf, entropy, len`。**这张表是后面所有工作的唯一入口**，之后调阈值、画图、做统计都不许重新跑模型。
- 本周交付：`features.csv`（约 4400 行 × 15 列）+ 一页数据字典。

## 5.2 W12–W13（01/18–01/31）：校准与首轮主表

- 开发集（20%）上学融合权重：逻辑回归或极简线性加权即可，别上复杂模型——本科生用 LR 反而好解释、好写进论文。
- 校准集（30%）上做三件事，并做对比：温度缩放、等渗回归、split conformal（取分位数给风险上界）。用 Clopper–Pearson 给"实际错误率 ≤ α"的置信区间。
- 测试集（50%）只在 W13 打开一次，报告 coverage / risk / AURC / ECE / p95 时延。
- 六组基线在测试集上跑齐，主表成型。

## 5.3 W14（02/01–02/07）：春节缓冲，只写作

春节在 2027-02-06 前后，这一周不安排任何吃卡的任务。唯一的产出是第 4 章（方法）草稿 4000 字：把"断言分解 → 支持度 → 覆盖度/矛盾度 → 融合 → 校准 → 决策"这条链写成公式加文字。此时你手里有全部中间结果，写起来最快。

## 5.4 W15–W17（02/08–02/28）：消融、分域、种子

- 六组消融，一次只改一个因素：去矛盾度、去覆盖度、去检索质量、去校准（改用固定阈值）、断言级改句子级、换生成模型（在 500 题子集上跑）。
- 分领域报告（CRAG 五个领域），这是"阈值要不要分域"的证据。
- 三个随机种子（采样与 LLM 输出有随机性），报告均值与方差；主表数字给 bootstrap 1000 次的 95% 置信区间，基线比较用配对 bootstrap 检验。
- 本周交付：消融表 v2 + 分域表 + 方差表。

## 5.5 W18–W19（03/01–03/12）：人工复核与结果冻结

# 十一　复现路线：五步，每步都有"跑通标准"

复现不是"把别人的仓库跑起来"，而是"用我自己的代码，在同样的数据上，得到能被解释的数字"。五步如下，任何一步不达标就不要进下一步。

表 11-1　五步复现路线
| 步 | 做什么 | 跑通标准 | 预计工时 | 卡在哪最常见 |
|---|---|---|---|---|
| 1 | 跑 CRAG 官方示例与评测脚本 | 官方给的样例预测能得到合理分数 | 3 h | 依赖版本、数据路径、分词器下载 |
| 2 | 自建最小闭环（BM25 + API 生成，20 题） | 20 题跑通、格式正确、能人工判对错 | 4 h | prompt 让模型输出非 JSON |
| 3 | 全量基线（BM25/稠密/混合 + 重排开关） | 四组检索配置在同一评测脚本下出表 | 8 h | 索引内存、批大小、显存 |
| 4 | 主方法（断言级信号 + 校准 + 决策） | `features.csv` 生成、主表带 CI | 20 h | 断言粒度不稳、NLI 阈值飘 |
| 5 | 消融与稳健性（6 组 + 3 seeds） | 每次只改一个因素，结果可复现 | 12 h | 忘记固定种子、prompt 被悄悄改动 |

对第 1 步的补充：如果官方仓库跑不通（很常见），**不要在上面耗超过一天**。改用"官方数据 + 自己写的评测"：三档判定的定义在论文里写得很清楚，自己实现一遍反而更可控，也正好是任务书里"可复现评测框架"的一部分。
