# 一　这份计划怎么用

这份文档不是"理想情况下的学习路线"，而是一张按日历排死的施工表。它的排法遵循四条规则，先说明规则，你才知道为什么某一周只有一件事。

- **每周只有一个主任务**。一周内允许穿插阅读和小修，但只允许有一个"这周必须交付"的东西。本科毕设最常见的失败不是能力不够，而是每周都很忙、每周都没有可检查的产出。
- **先复现，再做方法对照**。先对齐官方数据与评测，复现 LLM-only 和 Task 1 摘要拼接基线。再比较检索配置、建立三维评分，并验证重检索、重新生成和拒答分支。缓存首轮产物以复用评分与生成结果。
- **里程碑倒排**。学院的开题（12-25）、中期（03-15 至 03-26）、内审查重（04-26 起）、答辩（05-18 起）是硬边界，不可协商。本计划把"结果冻结"放在中期之前，把"写作"分散到 4 次，而不是留到最后一个月。
- **算力按需错峰**。建索引、全量生成这类一次性重活放在寒假前和寒假初，宿舍/实验室卡空闲时段（夜间、周末）跑批；白天只做读、写、调脚本这类不吃卡的工作。

计划用 **α** 表示选择性风险分析中的目标错误率上限，用 **τ** 表示接纳阈值。各分项的触发阈值也在独立校准集上确定。

# 三　P0 预研（W1–W3）：把题目钉死，把环境跑通

这三周的目标不是学知识，而是把三个不确定性消掉：题目能不能被导师接受、数据能不能下载、代码能不能跑起来。

## 3.1 W1（11/02–11/08）：确认题目 + 装环境 + 下载数据

本周七件事，按顺序做，一天一件：

1. **与导师核对任务书。** 确认检索配置对照、三维一致性评分、自适应动作与 CRAG 评测的交付形式。
2. **确认做院内、跨院还是校外毕设**。若走校外，10-31 前必须把《校外完成本科毕业设计（论文）审批表》和协议交到教三楼 811；已过期的要第一时间联系王老师问补交口径。境外/校外一律回校答辩。
3. 装 Python 环境：`conda create -n ragqa python=3.10`，装 `torch`（按服务器 CUDA 版本）、`transformers`、`sentence-transformers`、`faiss-cpu`、`bm25s`（不要用 `rank_bm25`，它在百万级语料上要吃 10—20 GB 内存）、`jieba`、`pandas`、`scikit-learn`、`matplotlib`、`tqdm`。本周先只装 CPU 版，能跑通即可。
4. 从官方 CRAG 仓库获取 Task 1 数据，核对题量、划分和字段，解包到 `data/raw/crag/`。[数据说明](../data/README.md)
5. 核对原课题中 `RAG` 对应的数据集全名和版本。RGB 负例只用于可选补充实验。
6. 建 Git 仓库，写 `README.md`：一段话说明题目、一段话说明目录、一段话说明复现命令。第一周就把这件事做掉，后面 30 周的实验记录都靠它。
7. 读第一批论文（见第五章 Batch A，5 篇），每篇在 `notes/` 下写 200 字摘要，格式固定：问题 / 方法 / 指标 / 我能借用什么。

本周验收：能用自己的话在 3 分钟内讲清"我要解决什么问题、用什么信号、在什么数据上评、和谁比"，且导师认可这个范围。

## 3.2 W2（11/09–11/15）：系统选题 + 第一个能跑的东西

- **11-09 00:00 至 11-16 00:00 必须在教务系统完成选题**（毕业设计 → 选题管理 → 学生选题），状态要变成"确定"才算完成。最多填 3 个平行志愿，被任一教师反选后不得无故更换，所以第一志愿要填你已经和导师谈妥的那个。
- 代码任务：用 BM25 在 20 道题上跑通"检索 top-5 → 拼 prompt → 调一次模型 → 输出答案"的闭环。模型这周可以用 API（便宜、免装），先把链路跑通。
- 数据集任务：先按仓库默认字符窗口切块，检查 `data/interim/chunks.jsonl` 的块数与长度，再在检索实验中调整切分参数。
- 读第二批论文（Batch B 前 2 篇）。
- 本周验收：用 `01_prepare_data.py`、`02_build_index.py` 和 `03_generate.py --limit 20` 跑 BM25 冒烟，检查证据 ID、答案格式和输出题数。模拟或真实生成配置见[仓库说明](../README.md)。

## 3.3 W3（11/16–11/20）：任务书定稿

任务书由导师下达、你配合填写。本周把六栏内容写成定稿，直接可用《01_毕设完成路线与技术调研》第九章的文字：

- 主要内容包括三种检索基线、切分和召回数及重排序方法对照、三维一致性评分、自适应动作与复验、统一评测和错误案例分析。
- 技术要求包括官方数据划分、独立校准、同题配对对照、答案准确率、拒答准确率、推理延迟与可复现快照。
- 主要参考文献：从第十章挑 10 篇，按 GB/T 7714 格式排好。
- 进度安排：按本文件第二章的四段式写（11–12 月框架与开题；1–2 月评分、校准与主实验；3 月消融与中期；4–5 月论文、查重与答辩）。
- 题目类型勾"研究设计类"，题目来源按实际填。

本周验收：任务书提交且导师签字，同时确认服务器环境可跑正式基线。[服务器部署指南](服务器部署指南.md)

# 四　P1 开题（W4–W8）：五周把"能跑的实验"变成"能开题的方案"

开题报告 11-30 至 12-25 提交并接受学院检查。技术交付包括公开基线复现记录、开发集检索对照表和三维评分原型。开发集可先用约 200 题做调试。

## 4.1 W4（11/23–11/29）：官方评测接入与基线复现

- 接入 CRAG 官方划分，保留 `interaction_id`、`query_time` 和答案别名。用一小批验证集确认评判、缺失输出处理和推理时间记录。
- 复现 Llama 3 8B Instruct 的 LLM-only 与网页摘要拼接。记录模型、提示词、评判器版本及与论文设置的差异。该复现单独记录，后续检索和决策调试继续使用开发集。[CRAG 官方实验设置](https://arxiv.org/html/2406.04744#S5.SS1)
- 本周验收为评测能输出 Correct、Incorrect、Missing 数量，逐题预测能与官方题目对齐。

## 4.2 W5（11/30–12/06）：检索与重排序对照

- 各检索配置共享同一生成后端和模型。优先复用已经跑通的 vLLM 服务，使用兼容 API 时记录服务与模型版本。
- Prompt 固定版本号（`prompt_v1`），要求模型输出 JSON：`{"answer": ..., "citations": [块编号]}`。加引用编号是后面断言级校验的入口，这一步不要省。
- 接入向量检索与混合检索。先对齐切分、召回数、生成器和评判器，再分组比较固定窗口与按句界切分、不同 top-k，以及保持首轮排序、交叉编码器重排序和 MMR 重排序。重排序组共享候选块和上下文预算。记录准确率、时延和有标注子集的检索指标。
- 本周验收为约 200 道开发题的配置对照表。抽查证据 ID、引用和生成输出的对应关系。

## 4.3 W6（12/07–12/13）：断言分解 + NLI 打分

- 断言分解：用 LLM 把答案拆成原子断言（一句一断言、不含指代、可独立判真假），落 `claims.jsonl`。抽 20 题人工检查，断言数过多（>8）或过少（<1）都要调 prompt。
- 用现成 NLI 或事实核查模型生成断言与证据的支持和矛盾分数，另计算问题与证据的检索相关性，以及证据覆盖问题所需信息的充分性。
- 本周验收为能逐题输出三个分项和融合分数。人工核对包含「答案断言均有支撑，但证据不足以回答完整问题」的案例。

## 4.4 W7（12/14–12/20）：基线与曲线

- 跑普通 RAG 与仅验证后拒答，两者共享首轮候选答案。模型自评阈值可作为补充对照。
- 复用 `src/mvs/eval/metrics.py` 的风险–覆盖函数，报告开发集答案准确率、幻觉率和拒答率。
- 开题报告开始写：本周完成"选题背景与意义"和"研究的基本内容与拟解决的主要问题"。

## 4.5 W8（12/21–12/25）：开题定稿

- 开题报告 ≥1500 字、参考文献 ≥10 篇（近五年为主）。结构按模板五段写：背景与意义 / 研究内容与拟解决问题 / 研究方法及措施 / 工作步骤与进度 / 主要参考文献。
- 直接把 W7 的风险—覆盖曲线、W4 的指标表放进报告，比任何文字都有力。
- 准备 5 分钟开题陈述：问题（1 句）→ 为什么现有方法不够（1 句）→ 我的信号（1 句）→ 怎么验（1 句）→ 进度（1 句）。
- 本周验收：开题报告上传系统、导师审核通过；PPT 能讲 5 分钟不超时。

# 五　P2 主实验（W9–W19）：十一周把主表做出来

这是全篇最重的一段，跨期末、寒假、春节。核心策略是：**期末周只做低强度工作（写、读、整理），寒假集中跑重活**。

## 5.1 W9–W11（12/28–01/17）：固化首轮与跑通重试分支

- W9 固定首轮检索、重排序和生成配置，缓存开发集与校准集的证据、答案和时延。
- W10 批量计算检索相关性、答案支持度和证据充分性。在开发集选择融合权重，复核错误证据、答案与证据矛盾、证据不足三类案例。
- W11 跑通动作选择。重检索更新证据再生成，重新生成沿用已有证据。首版每题最多追加一次重试，无可用重试动作或复验仍未达标时拒答。保留首轮与复验的证据、答案、分项分数、动作、拒答原因和耗时。
- 阶段交付为 `features.csv`、动作轨迹和数据字典。阈值后处理可复用中间量。改变检索结果、重试提示词或路由时，需评测对应分支输出。

## 5.2 W12–W13（01/18–01/31）：校准与首轮主表

- 从官方 `split=0` 划出互斥的开发集和校准集。W12 在校准集确定接受、检索相关性、证据充分性和答案支持度的阈值，冻结策略与消融配置。风险–覆盖是辅助分析，风险上界需说明统计假设和阈值选择方式。
- W13 在官方 `split=1` 上报告预先确定的检索类型、切分、召回数及重排序方法对照。决策主表比较普通 RAG、仅验证后拒答和完整方法，固定首轮检索、生成器与评判器。
- 主表报告答案准确率、基于独立标注子集的拒答准确率、推理延迟 p50/p95，并记录幻觉率、未作答率、各动作触发比例与复验结果。拒答准确率在独立标注完成后填写。

## 5.3 W14（02/01–02/07）：春节缓冲，只写作

春节在 2027-02-06 前后。这一周安排方法章草稿，写清三维评分、动作阈值、两条重试分支及复验规则。

## 5.4 W15–W17（02/08–02/28）：消融、分域、种子

- W15 分别去掉检索相关性、答案支持度和证据充分性。使用预先确定的缺省路由规则，在校准集重新确定相关阈值。
- W16 分别禁用重检索和重新生成。关闭某分支时，该分支原本会触发的样本直接拒答。用仅验证后拒答组观察同时关闭两条分支的结果。
- 分领域报告（CRAG 五个领域），这是"阈值要不要分域"的证据。
- 三个随机种子（采样与 LLM 输出有随机性），报告均值与方差；主表数字给 bootstrap 1000 次的 95% 置信区间，基线比较用配对 bootstrap 检验。
- 本周交付：消融表 v2 + 分域表 + 方差表。

## 5.5 W18–W19（03/01–03/12）：人工复核与结果冻结

- 抽约 100 条做分层复核。先基于每题固定候选证据池标记应答或应拒答，再核对各方法的答案、断言和拒答理由。报告标注口径、样本量和一致性。
- 归因覆盖检索失效、生成不一致、评分误判、决策失误和候选池缺证据。记录代表性样本首轮与复验的变化，并用成功修复与正确拒答作对照。[错误归因口径](01_毕设完成路线与技术调研.md)

# 十一　复现路线：五步，每步都有"跑通标准"

复现不是"把别人的仓库跑起来"，而是"用我自己的代码，在同样的数据上，得到能被解释的数字"。五步如下，任何一步不达标就不要进下一步。

表 11-1　五步复现路线
| 步 | 做什么 | 跑通标准 | 预计工时 | 卡在哪最常见 |
|---|---|---|---|---|
| 1 | 跑 CRAG 官方示例与评测脚本 | 官方给的样例预测能得到合理分数 | 3 h | 依赖版本、数据路径、分词器下载 |
| 2 | 自建最小闭环（BM25 + API 生成，20 题） | 20 题跑通、格式正确、能人工判对错 | 4 h | prompt 让模型输出非 JSON |
| 3 | BM25／向量／混合检索及重排、切分、召回数对照 | 同题集输出检索配置对照表 | 试跑后估算 | 索引内存、批大小、显存 |
| 4 | 三维一致性评分、自适应动作和复验 | 同题比较普通 RAG、仅验证拒答与完整方法 | 试跑后估算 | 阈值敏感、重试输出未留档 |
| 5 | 评分与动作消融 | 每次只改一个因素，逐题结果与延迟可复核 | 试跑后估算 | 阈值或初始配置未对齐 |

对第 1 步的补充：如果官方仓库跑不通（很常见），**不要在上面耗超过一天**。改用"官方数据 + 自己写的评测"：三档判定的定义在论文里写得很清楚，自己实现一遍反而更可控，也正好是任务书里"可复现评测框架"的一部分。
