# 一　结论先行

在展开之前，先把六条判断放在最前面。后面所有章节都是在为这六条提供依据，如果你的时间只够看一页，看这一页。

- **课题包含三部分。** 搭建可复现的 RAG 框架并比较 BM25、向量检索、混合检索与重排序。设计融合检索相关性、答案受证据支持程度和证据充分性的轻量评分。依据评分触发重检索、重新生成或拒答，在 CRAG 上衡量效果与额外延迟。
- **分两阶段做对照。** 先固定生成器评估切分、召回数和重排序，再固定首轮检索与生成配置，比较普通 RAG、仅验证后拒答和完整自适应方法。保留风险–覆盖分析，检验拒答带来的可靠性收益。
- **毕设评的是"证据链是否完整"，不是"指标是否 SOTA"。** 问题 → 假设 → 基线 → 消融 → 统计检验 → 失败案例 → 结论边界，七环齐全就是合格甚至良好；缺任何一环，指标再高也会在中检或答辩被问穿。
- **真正的风险不在算法，在评测。** 阈值泄漏、LLM 裁判偏差、检索召回天花板、断言粒度漂移，这四个坑会让你的"提升 2 个点"变成无效结论。第六章表 6-2 给出对应的防御措施，请当成硬约束执行。
- **按实测吞吐估算算力。** 用小样本分别记录向量编码、重排序、生成、验证和触发重试的耗时。缓存可复用的证据与初次生成结果，校准和统计分析可在 CPU 上完成。
- **时间要按"三段"用，而不是按"均匀努力"。** 开题前 8 周打地基（能跑 + 能评），寒假 6 周出结果（主表 + 消融），春季 8 周写作与补实验。春节期间降级为写作周，不要安排吃卡任务。

# 三　本科毕设到底在评什么

## 3.1 一张证据链

评委判断"这是不是一篇合格的毕设"，实际上是在检查一条证据链是否闭合。七环缺一不可：

- **问题**：一句话，含对象、机制、条件。"RAG 在证据不足时仍强行作答"是问题；"RAG 还不够好"不是问题。
- **假设**：可被证伪。例如"断言级覆盖率与矛盾度的联合信号，对答案正确性的判别力（AUC）显著高于模型自评分"。
- **基线**：至少三组，且包含"最强的土办法"（模型自评阈值）。没有基线的提升等于没有提升。
- **消融**：每次只改一个因素，证明"是核心组件在起作用"，而不是"整体调参的副作用"。
- **统计**：在同一测试题集上计算配对置信区间，随机采样方案另报告种子间差异。
- **案例**：至少 3 个失败案例，能归因到信号、校准或检索中的某一类。
- **边界**：明确说清"在什么条件下不成立"（换模型、换领域、检索全错时）。

# 四　技术调研：RAG 可靠性的研究地图

## 4.1 问题从哪来：三个失效模式

RAG 的可靠性问题可以拆成三个互不重叠的失效模式，它们各自对应不同的研究线。把这三者混为一谈，是选题失控的根源。

- **检索侧失效**：正确证据没被召回，或召回了大量噪声。研究线是查询改写、检索纠错、自适应检索。
- **生成侧失效**：证据在上下文里，但答案与之不一致（无支撑、过度概括、数字错位）。研究线是事实核查、引用生成、自验证。
- **决策侧失效**：候选内容无法支持回答时，系统仍然强行作答。研究线是弃权（abstention）、选择性预测和风险控制。

三类失效分别对应检索配置对照、答案–证据一致性评分和自适应动作选择。检索实验先测量证据选择对问答的影响。进入方法对比时，各方法共享首轮检索配置，触发重检索后允许证据发生变化。

## 4.2 五条技术路线对照

表 4-1　五条路线与本科可行性
| 路线 | 代表工作 | 典型指标 | 本科可行性 | 本课题是否采用 |
|---|---|---|---|---|
| L1 检索纠错与自适应 | Corrective RAG、Adaptive-RAG、Self-RAG 的 retrieve 分支 | 准确率、检索调用次数 | 可限制单题追加检索次数 | 用一致性评分触发重检索，继续使用当前题目的候选页 |

### 检索与重排序对照

先在相同切分、召回数和输入预算下比较 BM25、向量检索和混合检索。随后用同一检索器比较固定窗口和按句界合并两种切分方式，再分别改变窗口长度或重叠、首轮召回数量。做重排序对照时，各方法共享同一批候选块和相同的上下文预算。计划比较保持首轮排序、交叉编码器重排序和 MMR 重排序。交叉编码器联合评估问题与候选文本的相关性，MMR 在相关性之外考虑已选内容的冗余。[交叉编码器说明](https://sbert.net/docs/cross_encoder/usage/usage.html) · [MMR 原论文](https://doi.org/10.1145/290941.291025)

### 决策流程

分别计算检索相关性 `R`、答案支持度 `A` 和证据充分性 `E`，再融合成一致性分数 `S`。`R` 描述证据与问题的相关性。`A` 依据断言与证据的支持和矛盾关系。`E` 判断当前证据能否覆盖回答问题所需的信息。首版用现有模型和规则计算分项，经归一化后做轻量加权融合，并保留各分项用于动作选择和消融。

| 判断条件 | 动作 |
|---|---|
| 一致性及三个分项均达标，且无实质矛盾 | 直接回答并返回引用 |
| 检索相关性低或证据不足，且仍可补充证据 | 在本题配套网页内改写查询或扩召回，更新证据后生成新答案 |
| 检索相关性和证据充分性达标，但答案支持度低、存在矛盾或融合分数未达标 | 保留证据，根据校验反馈重新生成答案 |
| 候选池为空、没有可用的重试动作，或复验仍未达标 | 拒答并记录原因 |

首版每题最多追加一次重试，作为控制延迟的实验预算。重检索后的生成计入同一分支。重试后用相同口径对更新的答案和证据重新评分，并记录首轮、动作、复验结果、拒答原因和时延。两条重试分支可分别关闭，用于配对消融。

## 4.3 本课题在文献中的位置

本课题以答案–证据一致性作为反馈，检验能否补回可用证据、修正不受支持的答案，并识别应当拒答的样本。用答案准确率、拒答准确率与推理延迟衡量收益和代价，结合断言定位、动作轨迹及失败案例解释结果。

有两篇工作必须知道，因为它们决定了你的"立论"和"差异化"怎么写：

- **Sufficient Context（ICLR 2025, arXiv:2411.06037）** 把"上下文是否充分"从"答案是否正确"里独立出来，主张充分则答、不充分则该弃权。这是本课题最直接的思想来源——它给了你"充分性是一个独立可判的量"这个合法性，也给了你第一章立论的引文。**你的增量在于：把它的"充分/不充分"二分细化为断言级的覆盖度与矛盾度，并把决策从"提示模型判断"换成"校准 + 风险约束"。**
- **SURE-RAG（arXiv:2605.03534, 2026）** 把答案级证据判为 Supported / Refuted / Insufficient 三态，再联合不确定性做选择性回答。这是与你**结构最接近的同期工作**，开题报告与论文的相关工作必须点名它，并说清差异（见下表第一行）。若能拿到全文，读它的实验设置与阈值做法，避免做出一个"更弱的重复"。

## 4.4 撞车风险与差异化

写开题与相关工作前必须知道别人做到哪一步，否则会被评委一句话问穿。下表按"威胁程度"从高到低排列，前两行是你必须正面对应的：

表 4-2　撞车风险与差异化说法
| 已有工作 | 它做了什么 | 它没做什么 | 我的差异化说法 |
|---|---|---|---|
| SURE-RAG（2026） | 结合证据三态判定和不确定性进行选择性回答 | 关注对答案的整体判定 | 以断言级支持度和问题证据充分性选择重试动作 |
| Sufficient Context（ICLR 2025） | 单独判断上下文是否足以回答问题 | 关注充分性和模型作答之间的关系 | 把充分性作为重检索的触发信号，与答案支持度共同用于决策 |
| Self-RAG | 用训练得到的反思标记调节检索、生成与批评 | 判定机制集成在生成模型中 | 使用独立一致性评分模块，为现有生成器提供反馈 |
| RAGChecker | 用 claim 级蕴含关系诊断 RAG，指出检索错还是生成错 | 诊断工具，不用于在线决策，不控制风险 | 我借用其"claim 级"思想，但目标是决策与风险控制，不是事后诊断 |
| RAGAS / ARES | 无参考评测 RAG 的若干维度 | 指标是"分数"，不是"决策"，无弃权机制 | 我把评测指标直接接到决策上，形成闭环 |
| RGB 的负例拒答 | 用"能否识别无答案问题"测拒答能力 | 只报告准确率，不报告风险—覆盖权衡 | 我报告 risk-coverage 与 AURC，并给出 α 的可解释含义 |
| AbstentionBench / RefusalBench | 系统评测 LLM 在不可答问题上的弃权（后者面向有据模型） | 面向通用模型或评测规模，非 RAG 管道内的可部署决策 | 我在 RAG 管道内做，且给出可落地的阈值校准流程与拒答理由 |

## 4.5 三种"看起来聪明、实际做不动"的做法

- **训练一个 critique / verifier 模型**：需要标注数据与训练资源，本科阶段性价比极低，且一旦效果不如现成 NLI，整篇论文失去支点。
- **把阈值调到最优再报告**：这是最常见的隐性作弊，评委会问"你的阈值是在哪批数据上定的"。必须三段划分。
- **控制检索对照规模。** 先在相同切分和召回数下比较 BM25、向量与混合检索，再围绕选定配置逐项改变切分、召回数和重排序。保留对照用的初始配置和逐题结果。

# 六　方法论：可复现的实验怎么做

## 6.1 三段数据划分

正式实验以 Meta CRAG Task 1 为主。`01_prepare_data.py` 保留官方 `split=1` 的 1,335 道公开测试题，仅从 `split=0` 的验证集按题目 ID 划出开发集和校准集。开发集选择检索配置与评分权重，校准集确定动作阈值，测试集用于报告预先确定的对照。[数据说明](../data/README.md)

复现阶段先对照 CRAG 论文表 11。Llama 3 8B Instruct 的 LLM-only 准确率为 23.7%，原顺序拼接网页摘要的 Task 1 准确率为 28.5%。记录模型、输入构造和评判器版本。相关工作中，PruningRAG 表 2 的五网页实验使用标准化 CRAG，报告 Naive RAG 24.80% 和 Self-RAG 14.29% 的准确率。比较时保留各论文的数据处理与评判口径。[CRAG 表 11](https://arxiv.org/html/2406.04744#A3.SS2) · [PruningRAG 表 2](https://arxiv.org/html/2409.13694#S3)

## 6.2 指标定义

- **答案准确率**为最终判定 Correct 的题数除以测试集总题数。同步报告 CRAG 的 Incorrect（幻觉）和 Missing（未作答）占比，执行失败也保留逐题记录和失败率。各方法使用相同的判定口径和评判器版本。
- **拒答准确率**在独立标注子集上计算，为作答或拒答动作与「应答／应拒答」标签一致的题数除以该子集题数。以每题固定候选证据池和查询时间为依据，有充分证据支持答案或指出题目错误前提的样本标为「应答」。各方法共享标签。报告标注规则、样本量和拒答率，并单独记录执行失败。CRAG 的 Missing 用于计算未作答率。[CRAG 官方提示词](https://arxiv.org/html/2406.04744#A3.SS1)
- **推理延迟**报告端到端 p50、p95。计时从检索到最终响应，包含重排序、校验、重试与决策，在相同硬件、并发和计时口径下比较。另记录额外调用次数与分阶段时延。
- **覆盖率**为最终接纳作答数除以总题数。**选择性风险**为已接纳样本中的错误比例，零接纳时记为不适用。风险–覆盖曲线和 AURC 用于补充比较拒答策略。对已经冻结的候选答案，可通过扫接纳阈值计算曲线。改变重试路由的策略需要评测相应动作输出。
- **检索诊断**在有可靠证据标注的子集上报告 Recall@k 或 nDCG。CRAG Task 1 的公开网页字段未提供逐页 `support`，可人工复核子集并报告标注范围。

## 6.3 统计

- 主表每个数字给 bootstrap 1000 次重采样的 95% 置信区间。
- 基线比较用配对 bootstrap 检验（同一批题目上配对，比独立检验更敏感）。
- 随机性来源（采样、LLM 输出、数据顺序）至少跑 3 个种子，报告均值与方差。
- 人工复核算 Cohen's κ，报告与自动判定的一致率。

## 6.4 实验记录规范

这四条是"能不能复现"的分水岭，成本极低：

- **逐题汇总表**按 `run_id` 和 `qid` 对齐各方法，记录初始和最终判定、三维分数、触发动作、拒答标记及时延。证据 ID、答案和调用轨迹保留在 run 目录中。评分或阈值后处理可复用中间量，改变检索、重排序或重新生成配置时运行相应分支。
- **快照**：每次定稿性实验产出 `results/snapshots/YYYY-MM-DD/`，内含结果文件、配置文件、git commit、随机种子。
- **配置哈希**：把 config 序列化后取哈希写进结果文件名，避免"这份结果是哪版 prompt 跑的"这种问题。
- **数据字典**：一页纸说明 `features.csv` 每列含义与取值范围，写在 `docs/data_dict.md`。

## 6.5 错误归因五类

失败案例不要写成"举几个错例"，要写成分类统计。五类足够：

表 6-1　错误归因分类
| 类别 | 判定依据 | 该类的改进方向 |
|---|---|---|
| 检索失效 | 候选池有可用证据，但召回结果遗漏证据或前排噪声过多 | 比较切分、召回数、重排序与重检索 |
| 生成不一致 | 给定证据足以回答，生成答案缺乏支持或与证据冲突 | 检查重新生成能否修复 |
| 评分误判 | 断言分解、证据校验或充分性评估与人工判断不一致 | 检查分项分数和融合权重 |
| 决策失误 | 误拒、错误接纳、选择无效重试，或重试引入新错误 | 核对动作与阈值，记录首轮到最终结果的变化 |
| 候选池缺证据 | 任务提供的全部候选内容仍不足以支持作答 | 检查是否正确拒答，记录重检索的适用边界 |

每类保留代表性案例的题目、首轮证据与答案、分项分数、触发动作、复验和最终结果。将正确拒答及成功修复作为对照案例一并记录。

## 6.6 六个陷阱与对应防御

表 6-2　评测陷阱
| 陷阱 | 表现 | 防御 |
|---|---|---|
| 候选证据缺失 | 本题配套网页中缺少作答所需证据 | 区分候选池本身缺证据和检索漏召回，记录重试结果与拒答原因 |
| 阈值泄漏 | 用测试结果反复调阈值 | 用开发集和校准集确定配置，预先冻结测试对照 |
| LLM 裁判偏差 | 位置偏好、长度偏好使正确率虚高 | 交换 A/B 顺序；抽 100 条人工核对 |
| 答案长度混淆 | 长答案置信度天然偏低 | 分长度层报告 |
| 领域漂移 | CRAG 五领域难度差异大，统一阈值可能过度拒答 | 分域报告 + 分域校准对照 |
| 断言粒度漂移 | 粒度一变覆盖度全变 | 固定粒度，另做一次粒度敏感性分析 |

## 7.2 摘要怎么写

中文摘要 400—600 字，四句话结构，一句都不能虚：

1. **背景与问题**：RAG 在证据不足时仍强行作答，是幻觉的重要来源，现有系统缺乏可量化、可解释的自判断能力。
2. **方法**：融合检索相关性、断言级答案支持度和证据充分性，按评分选择回答、重检索、重新生成或拒答，并对重试结果复验。
3. **结果**：根据 CRAG 实测结果填写答案准确率、拒答准确率与推理延迟的变化，并汇报典型的修正和失败案例。
4. **意义**：说明方法在不同证据条件下的适用范围和额外计算代价。

关键词可用检索增强生成、答案自验证、答案–证据一致性、重排序和拒答机制。

# 八　答辩怎么准备

## 8.1 十分钟陈述的结构

- 问题与动机（2 分钟）：说明检索噪声、答案缺乏支持和证据不足仍作答三类失效。
- 方法（4 分钟）：用架构图说明三维评分如何触发重检索、重新生成和复验拒答。
- 实验（4 分钟）：检索对照、决策主表与分支消融，汇报准确率、拒答与时延的变化。
- 结论与局限（2 分钟）：用案例说明配套证据缺失时的拒答表现，并给出额外时延与分域结果。

## 8.2 八个必答题与 30 秒答法

表 8-1　必答题准备
| 问题 | 答题骨架 |
|---|---|
| 你的创新点是什么 | 三维一致性评分、基于评分分项的动作选择、配对评测与分支消融 |
| 和 Self-RAG 有什么区别 | Self-RAG 用训练得到的反思标记调节检索和生成。本课题在现有生成器外接评分模块，依据证据与答案状态选择动作 |
| α 怎么定 | α 是风险预算。若报告风险上界，说明候选阈值的选择方式、置信水平和适用假设 |
| 样本量够不够 | 官方公开测试集 1,335 题。报告配对置信区间，并说明拒答标注子集的实际规模 |
| 换个模型还成立吗 | 已在 500 题子集上换模型复跑，趋势一致（或：不一致，说明方法对模型敏感，这是局限） |

## 8.3 三个"送命题"

- **候选证据缺失时如何处理？** 说明重检索只能从任务提供的候选页中补找证据，展示复验失败后的拒答及其局限。
- **模型自评可以替代证据评分吗？** 若做了该对照，依据实测的风险、覆盖率和证据定位结果作答。
- **"这算工程还是算研究？"** 正确答案是"研究，因为核心是一个可证伪的假设（联合信号判别力优于单一信号），工程只是承载实验的载体"。

# 九　可直接使用的开题与任务书文字

## 9.1 研究内容

1. 构建面向知识密集型问答的可复现 RAG 框架，实现 BM25、向量和混合检索基线。
2. 比较不同文本切分、召回数量和重排序方法对问答结果的影响。
3. 设计轻量的答案–证据一致性评分模块，融合检索相关性、断言级答案支持度和证据充分性。
4. 依据评分选择重检索、重新生成或拒答，对重试后的答案与证据复验。在开发集选择评分配置，在独立校准集确定动作阈值。
5. 以 CRAG Task 1 为主要实验数据，报告答案准确率、拒答准确率和推理延迟，开展基线对比、消融与错误分析。原课题中并列的 `RAG` 待核对数据集全名及版本。[数据说明](../data/README.md)

## 9.2 技术路线（五步）

数据处理与索引 → BM25／向量／混合检索与重排序对照 → 生成与三维一致性评分 → 动作选择、复验及拒答 → CRAG 对比、消融与错误分析。

## 9.3 创新点（两条）

1. 用可定位到证据和断言的三维评分，检验它对无证据支持答案的识别能力。
2. 用评分分项选择补充证据、修正答案或拒答。通过配对消融检验各动作对准确率、拒答与时延的影响。

## 9.4 进度安排（四段）

- 2026 年 11—12 月完成官方基线复现、检索对照、评分原型与开题报告。
- 2027 年 1—2 月完成自适应分支、阈值校准、主实验和消融。
- 2027 年 3 月完成人工复核、错误分析与中期检查。
- 2027 年 4—5 月完成论文撰写、查重、内审与答辩准备。

## 9.5 预期交付

- 可复现的 RAG 实验框架，包括数据处理、检索与重排序、生成、评测入口及对应配置。
- 带答案自验证的 RAG 方法，包括三维评分、动作选择、复验与拒答，以及可检查的逐题证据和动作记录。
- 使用统一评测口径的基线对照、消融实验和错误案例分析，附实验配置、题目划分和结果快照。
