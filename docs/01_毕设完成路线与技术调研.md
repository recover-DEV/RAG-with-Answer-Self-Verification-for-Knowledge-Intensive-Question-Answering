# 一　结论先行

在展开之前，先把六条判断放在最前面。后面所有章节都是在为这六条提供依据，如果你的时间只够看一页，看这一页。

- **题目已经收得住了，不要再改。** 现题目把"搭框架 + 切分/召回对比 + 一致性评分 + 重检索/重生成 + 拒答 + 评测"六件事并列，实际工作量 18—20 周，超过本学期有效时间。收成"固定检索与生成组件 → 判定证据够不够 → 决定答不答"这一条主线后，范围小、变量少、结论可检验，正好是本科毕设该有的体量。
- **创新押在三个地方，不要训练模型。** 一是断言级的证据充分性信号（可解释、模型无关），二是把拒答建模为有限样本风险约束下的选择性预测（有校准与保形预测这套成熟数学工具），三是一套分层风险—覆盖评测协议（成本最低、最容易被复用）。这三样都不需要训练，只需要严谨。
- **毕设评的是"证据链是否完整"，不是"指标是否 SOTA"。** 问题 → 假设 → 基线 → 消融 → 统计检验 → 失败案例 → 结论边界，七环齐全就是合格甚至良好；缺任何一环，指标再高也会在中检或答辩被问穿。
- **真正的风险不在算法，在评测。** 阈值泄漏、LLM 裁判偏差、检索召回天花板、断言粒度漂移，这四个坑会让你的"提升 2 个点"变成无效结论。第六章表 6-2 给出对应的防御措施，请当成硬约束执行。
- **算力不是瓶颈。** 全流程约 65—130 GPU 小时（标准值约 104，含六基线、六消融与失败重跑），一张 24GB 消费级卡（4090/3090）足够，云上按需租用的学期账单在 350—450 元量级；反过来，笔记本 CPU 也能完成校准、阈值搜索、画曲线、统计检验这些最耗时思考的工作。核算过程见《03 服务器与算力方案》。
- **时间要按"三段"用，而不是按"均匀努力"。** 开题前 8 周打地基（能跑 + 能评），寒假 6 周出结果（主表 + 消融），春季 8 周写作与补实验。春节期间降级为写作周，不要安排吃卡任务。

# 三　本科毕设到底在评什么

## 3.1 一张证据链

评委判断"这是不是一篇合格的毕设"，实际上是在检查一条证据链是否闭合。七环缺一不可：

- **问题**：一句话，含对象、机制、条件。"RAG 在证据不足时仍强行作答"是问题；"RAG 还不够好"不是问题。
- **假设**：可被证伪。例如"断言级覆盖率与矛盾度的联合信号，对答案正确性的判别力（AUC）显著高于模型自评分"。
- **基线**：至少三组，且包含"最强的土办法"（模型自评阈值）。没有基线的提升等于没有提升。
- **消融**：每次只改一个因素，证明"是核心组件在起作用"，而不是"整体调参的副作用"。
- **统计**：置信区间 + 配对检验 + 多种子。单次运行的 +2 个点，在 4400 题上可能只是噪声。
- **案例**：至少 3 个失败案例，能归因到信号、校准或检索中的某一类。
- **边界**：明确说清"在什么条件下不成立"（换模型、换领域、检索全错时）。

## 3.2 四种典型的不合格

表 3-1　四种失败模式与早期信号
| 失败模式 | 长什么样 | 早期信号 | 本计划的防御 |
|---|---|---|---|
| 综述型 | 大段介绍 RAG、Transformer，没有自己的实验 | 第 3 周仍没有可运行代码 | W2 必须有 20 题闭环 |
| 堆功能型 | 做了重检索、重生成、Web 界面、多模型，但没有一个被验证有效 | 每周都在加功能，没有一张对比表 | 第 4 章的范围边界（明确不做） |

## 3.3 "创新"在本科阶段的准确定义

本科毕设不要求开创新方向，要求的是**可验证的增量**。增量分三层，做到哪层说哪层，不要越级吹：

- **第一层（合格）**：把已有方法在新场景/新数据上做严谨的实证，给出可信的比较与失败分析。
- **第二层（良好）**：在已有框架里替换一个组件，并用消融证明替换是有效的（例如把答案级自评换成断言级校验）。
- **第三层（优秀）**：给出一个带保证的机制（例如在风险上限 α 下的阈值选择流程），并证明它在多个领域可迁移。

本课题的设计正好覆盖三层：评测协议对应第一层，断言级评分对应第二层，风险受控阈值 + 跨域可迁移性对应第三层。**这也是为什么"不做重检索、不做重生成"是加分而不是减分**——它把有限的时间全部换成了证据。

# 四　技术调研：RAG 可靠性的研究地图

## 4.1 问题从哪来：三个失效模式

RAG 的可靠性问题可以拆成三个互不重叠的失效模式，它们各自对应不同的研究线。把这三者混为一谈，是选题失控的根源。

- **检索侧失效**：正确证据没被召回，或召回了大量噪声。研究线是查询改写、检索纠错、自适应检索。
- **生成侧失效**：证据在上下文里，但答案与之不一致（无支撑、过度概括、数字错位）。研究线是事实核查、引用生成、自验证。
- **决策侧失效**：证据不足、题目本身无解，系统仍然强行作答。研究线是弃权（abstention）、选择性预测、风险控制。

本课题只做第三条，并把第二条的一个组件（断言级支持度）作为信号来源。第一条只作为控制变量各跑一次。这个切分是整篇论文的骨架。

## 4.2 五条技术路线对照

表 4-1　五条路线与本科可行性
| 路线 | 代表工作 | 典型指标 | 本科可行性 | 本课题是否采用 |
|---|---|---|---|---|
| L1 检索纠错与自适应 | Corrective RAG、Adaptive-RAG、Self-RAG 的 retrieve 分支 | 准确率、检索调用次数 | 中：需要多轮检索，评测口径会膨胀 | 否（仅作控制变量） |
| L2 生成自省 | Self-RAG 的 critique token、Chain-of-Verification、Self-Refine | 事实性、幻觉率 | 低：需要训练 critique 模型或多次采样，成本高 | 否（作为背景与强基线引用） |
| L3 断言级事实核查 | MiniCheck、AlignScore、RAGTruth、RAGChecker、ALCE | 支持度 F1、citation precision/recall | 高：现成模型可直接调用，指标清晰 | **是（核心信号来源）** |
| L4 不确定性与校准 | Semantic Entropy、P(True)、温度缩放、等渗回归 | ECE、Brier、AUROC | 高：纯后处理，不需要训练 | **是（融合与校准）** |
| L5 选择性预测与拒答 | 经典 selective classification、RGB 负例拒答、AbstentionBench、保形预测 | risk、coverage、AURC | 高：数学工具成熟、代码量小、结论硬 | **是（核心决策机制）** |

这张表的读法是：L3 提供"分数"，L4 让分数"可比较"，L5 把分数"变成决策"。三者串起来就是本课题的方法链；L1、L2 是"别人已经做得很多、且对本科生性价比低"的两条路，摆在相关工作里讲清楚即可。

## 4.3 本课题在文献中的位置

用一句话定位：**不是"让 RAG 更准"，而是"让 RAG 知道自己什么时候不准，并且在证据不足时按风险预算拒答"。**

这个定位有三层好处。第一，它不与任何"提升准确率"的工作正面竞争，因此不需要打赢 SOTA 才能成立；第二，它的评价指标是 risk-coverage 曲线而非单点准确率，天然带置信区间，容易做出"看起来专业"的表；第三，它天然可解释——拒答时必须说出"哪条断言没有证据支持"，这正好回应了任务书里"可解释输出"的要求。

有两篇工作必须知道，因为它们决定了你的"立论"和"差异化"怎么写：

- **Sufficient Context（ICLR 2025, arXiv:2411.06037）** 把"上下文是否充分"从"答案是否正确"里独立出来，主张充分则答、不充分则该弃权。这是本课题最直接的思想来源——它给了你"充分性是一个独立可判的量"这个合法性，也给了你第一章立论的引文。**你的增量在于：把它的"充分/不充分"二分细化为断言级的覆盖度与矛盾度，并把决策从"提示模型判断"换成"校准 + 风险约束"。**
- **SURE-RAG（arXiv:2605.03534, 2026）** 把答案级证据判为 Supported / Refuted / Insufficient 三态，再联合不确定性做选择性回答。这是与你**结构最接近的同期工作**，开题报告与论文的相关工作必须点名它，并说清差异（见下表第一行）。若能拿到全文，读它的实验设置与阈值做法，避免做出一个"更弱的重复"。

## 4.4 撞车风险与差异化

写开题与相关工作前必须知道别人做到哪一步，否则会被评委一句话问穿。下表按"威胁程度"从高到低排列，前两行是你必须正面对应的：

表 4-2　撞车风险与差异化说法
| 已有工作 | 它做了什么 | 它没做什么 | 我的差异化说法 |
|---|---|---|---|
| SURE-RAG（2026，同期最接近） | 答案级三态判定（支持/反驳/证据不足）+ 不确定性，联合做选择性回答 | 粒度是整条答案而非断言；未见公开的风险上限保证与独立校准流程 | 我做断言级（可定位到"缺哪条证据"），并把阈值放到独立校准集上按 α 定，给出风险上界而非仅给经验曲线 |
| Sufficient Context（ICLR 2025） | 把"上下文是否充分"独立成一个可判的量，并指出充分性比正确性更适合决定是否弃权 | 判定仍依赖 LLM 自评式提示，不给统计保证，不做断言级定位 | 我用轻量 NLI 给出可复现的覆盖度/矛盾度，分数可校准、阈值可保证，且能指出缺失证据 |
| Self-RAG | 训练模型自己产出 critique token 决定是否检索/引用 | 需要训练、判定是答案级、无风险保证 | 我不训练，用现成 NLI 做断言级判定，且给出风险约束下的阈值 |
| RAGChecker | 用 claim 级蕴含关系诊断 RAG，指出检索错还是生成错 | 诊断工具，不用于在线决策，不控制风险 | 我借用其"claim 级"思想，但目标是决策与风险控制，不是事后诊断 |
| RAGAS / ARES | 无参考评测 RAG 的若干维度 | 指标是"分数"，不是"决策"，无弃权机制 | 我把评测指标直接接到决策上，形成闭环 |
| RGB 的负例拒答 | 用"能否识别无答案问题"测拒答能力 | 只报告准确率，不报告风险—覆盖权衡 | 我报告 risk-coverage 与 AURC，并给出 α 的可解释含义 |
| AbstentionBench / RefusalBench | 系统评测 LLM 在不可答问题上的弃权（后者面向有据模型） | 面向通用模型或评测规模，非 RAG 管道内的可部署决策 | 我在 RAG 管道内做，且给出可落地的阈值校准流程与拒答理由 |

## 4.5 三种"看起来聪明、实际做不动"的做法

- **训练一个 critique / verifier 模型**：需要标注数据与训练资源，本科阶段性价比极低，且一旦效果不如现成 NLI，整篇论文失去支点。
- **把阈值调到最优再报告**：这是最常见的隐性作弊，评委会问"你的阈值是在哪批数据上定的"。必须三段划分。
- **做端到端大网格搜索**（切分 × 召回数 × 重排 × 模型）：27 组配置起，每组一小时，光跑完就 135 小时。本课题只允许"各跑一次"。

# 六　方法论：可复现的实验怎么做

## 6.1 三段数据划分

把 CRAG 按题目 ID 哈希分成三份：开发集 20%（学融合权重）、校准集 30%（定阈值）、测试集 50%（只在最后报告一次）。按题目 ID 而非按样本划分，是为了让同一道题的不同变体不跨集，避免信息泄漏。若官方已给 dev/test，优先遵守官方划分，把 dev 再切两半。

这条规则是整篇论文可信度的地基。**在同一批数据上调阈值又在这批数据上报告结果，数字会虚高 5—10 个点**，而且无法在论文中自证清白。

## 6.2 指标定义

所有指标都写成公式，答辩时可以直接指着说：

- 覆盖率：coverage(τ) = |{i : Sᵢ ≥ τ}| / N
- 选择性风险：risk(τ) = |{i : Sᵢ ≥ τ 且答错}| / |{i : Sᵢ ≥ τ}|
- 风险—覆盖曲线：以 τ 为参数画 risk 随 coverage 变化的曲线；曲线下面积记为 AURC（越小越好）
- 校准误差：ECE = Σ_b (n_b / N) · |acc(b) − conf(b)|，按置信度分 10 个桶
- 时延：p95 端到端时延（检索 + 生成 + 校验 + 决策）
- 成本：单题 token 数与单题 GPU 秒数

## 6.3 统计

- 主表每个数字给 bootstrap 1000 次重采样的 95% 置信区间。
- 基线比较用配对 bootstrap 检验（同一批题目上配对，比独立检验更敏感）。
- 随机性来源（采样、LLM 输出、数据顺序）至少跑 3 个种子，报告均值与方差。
- 人工复核算 Cohen's κ，报告与自动判定的一致率。

## 6.4 实验记录规范

这四条是"能不能复现"的分水岭，成本极低：

- **单一入口宽表**：所有逐题中间量落到 `features.csv`，之后所有分析只读这张表，不再重跑模型。
- **快照**：每次定稿性实验产出 `results/snapshots/YYYY-MM-DD/`，内含结果文件、配置文件、git commit、随机种子。
- **配置哈希**：把 config 序列化后取哈希写进结果文件名，避免"这份结果是哪版 prompt 跑的"这种问题。
- **数据字典**：一页纸说明 `features.csv` 每列含义与取值范围，写在 `docs/data_dict.md`。

## 6.5 错误归因五类

失败案例不要写成"举几个错例"，要写成分类统计。五类足够：

表 6-1　错误归因分类
| 类别 | 判定依据 | 该类的改进方向 |
|---|---|---|
| 检索未召回 | 金标证据不在 top-k 里 | 检索侧（但本课题不研究） |
| 断言分解错 | 断言含指代、复合、或漏掉关键信息 | prompt 与粒度 |
| NLI 判错 | 人工看认为支持，模型判不支持（或反之） | 换模型 / 阈值 |
| 校准偏移 | 分数高但答错，且该领域整体偏移 | 分域校准 |
| 题目本身无解 | 语料里确实没有答案 | 这正是应该拒答的情形（正确行为） |

第五类要特别说明：它看起来像错误，实际是方法的正确表现，答辩时主动讲这一点非常加分。

## 6.6 六个陷阱与对应防御

表 6-2　评测陷阱
| 陷阱 | 表现 | 防御 |
|---|---|---|
| 召回天花板 | 金标证据根本没被召回，验证器无能为力 | 报告 oracle recall（用金标证据替换检索结果的上限） |
| 阈值泄漏 | 同批数据调阈值又测试 | 三段划分，测试集只开一次 |
| LLM 裁判偏差 | 位置偏好、长度偏好使正确率虚高 | 交换 A/B 顺序；抽 100 条人工核对 |
| 答案长度混淆 | 长答案置信度天然偏低 | 分长度层报告 |
| 领域漂移 | CRAG 五领域难度差异大，统一阈值可能过度拒答 | 分域报告 + 分域校准对照 |
| 断言粒度漂移 | 粒度一变覆盖度全变 | 固定粒度，另做一次粒度敏感性分析 |

## 7.2 摘要怎么写

中文摘要 400—600 字，四句话结构，一句都不能虚：

1. **背景与问题**：RAG 在证据不足时仍强行作答，是幻觉的重要来源，现有系统缺乏可量化、可解释的自判断能力。
2. **方法**：本文提出断言级证据充分性评分，将答案分解为原子断言并逐条校验支持与矛盾，融合检索质量与模型不确定性，用独立校准集在给定风险上限下确定拒答阈值。
3. **结果**：在 CRAG 上，相同风险水平下覆盖率相较模型自评基线提升 X 个百分点（95% CI: [a, b]），并给出缺失证据的定位信息。
4. **意义**：为 RAG 从"尽量答"走向"知道何时不答"提供了一套可复现、可迁移的评测与决策方案。

关键词 3—5 个：检索增强生成；证据充分性；选择性预测；保形预测；拒答机制。

# 八　答辩怎么准备

## 8.1 十分钟陈述的结构

- 问题与动机（2 分钟）：一张图讲清"检索有噪声 → 生成不忠实 → 证据不足仍作答"三级失效，指出后两级才是本文的战场。
- 方法（4 分钟）：一张架构图 + 一个公式（融合分数）+ 一个流程（校准定阈值）。不要念公式，指着图讲数据流。
- 实验（4 分钟）：主表（六基线，带 CI）+ risk-coverage 曲线 + 一组消融。只讲一条关键结论。
- 结论与局限（2 分钟）：明确说"检索全错时方法无效"、"阈值需要分域校准"，主动交底比被问出来强。

## 8.2 八个必答题与 30 秒答法

表 8-1　必答题准备
| 问题 | 答题骨架 |
|---|---|
| 你的创新点是什么 | 断言级信号（可解释）+ 风险约束阈值（有保证）+ 分层评测协议（可复用），三句话 |
| 和 Self-RAG 有什么区别 | 它训练 critique 模型做答案级判断；我不训练，用现成 NLI 做断言级判断，且给风险保证 |
| α 怎么定 | α 是业务给定的错误预算（如 5%）；我用 Clopper–Pearson 给实际风险 ≤ α 的置信上界 |
| 样本量够不够 | 测试集约 2200 题，主表给 bootstrap 95% CI，配对检验 p 值；小效应不做强结论 |
| 换个模型还成立吗 | 已在 500 题子集上换模型复跑，趋势一致（或：不一致，说明方法对模型敏感，这是局限） |
| 举一个错误案例 | 选"检索未召回"与"断言分解错"各一个，说明归因依据 |

## 8.3 三个"送命题"

- **"你的方法在检索完全失败时有用吗？"** 正确答案是"没有用，而且我知道边界在哪"——先给 oracle recall 上限，再说明本文方法的适用区间。硬撑会立刻失分。
- **"为什么不直接用 GPT-4 的置信度？"** 正确答案是把"模型自评阈值"作为基线之一，并展示它在同风险下的覆盖率更低。
- **"这算工程还是算研究？"** 正确答案是"研究，因为核心是一个可证伪的假设（联合信号判别力优于单一信号），工程只是承载实验的载体"。

# 九　可直接使用的开题与任务书文字

## 9.1 研究内容（三条）

1. 构建面向知识密集型问答的可复现评测框架：统一检索、生成与验证接口，支持 BM25、稠密与混合检索的切换，实现 CRAG 三档判定与风险—覆盖指标，全部中间量落盘。
2. 设计断言级的证据充分性评分：将答案拆分为原子断言，计算断言—证据覆盖度与矛盾度，结合检索质量与模型不确定性，经开发集学习权重、校准集校准。
3. 设计风险受控的拒答策略：在给定风险上限 α 下确定阈值，输出拒答理由与缺失证据定位，并在 CRAG 与 RGB 负例上完成对比、消融与错误分析。

## 9.2 技术路线（五步）

数据与索引（清洗、切块、建 BM25 与向量索引、固定评测口径）→ 基线与信号（六组基线，抽取检索/生成/验证三类信号）→ 评分与校准（融合分数，温度缩放/等渗/保形）→ 决策与解释（阈值、拒答理由、证据定位）→ 评测与分析（主实验、消融、分域、案例）。

## 9.3 创新点（两条）

1. 提出断言级、模型无关的证据充分性评分，把"答案是否可信"分解为可验证的覆盖度与矛盾度，相比答案级自评分具有更好的判别力与可解释性。
2. 把 RAG 的拒答建模为有限样本风险约束下的选择性预测问题，给出基于独立校准集的阈值确定方法，并配套分层风险—覆盖评测协议，验证阈值在 CRAG 多领域上的可迁移性。

## 9.4 进度安排（四段）

2026 年 11—12 月：完成实验框架、基线与开题报告；2027 年 1—2 月：完成评分、校准与主实验；2027 年 3 月：完成消融、分域实验与中期检查；2027 年 4—5 月：完成论文撰写、查重、内审与答辩。
